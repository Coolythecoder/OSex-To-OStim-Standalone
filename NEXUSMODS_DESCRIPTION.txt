[b]Short version[/b]

Adult Animation Pack Converter rebuilds supported animation pack archives into cleaner outputs for modern workflows. It does not edit your Skyrim folder directly. It creates a new output package or project folder, writes reports, and tells you what to do next.

[list]
[*][b]Ready-to-install workflow[/b] - build verified OStim Standalone, SexLab/SLAL, or SexLab P+/SLSB ZIPs.
[*][b]Authoring workflow[/b] - generate editable OStim Tools / AAC project folders or plain scene JSON folders for manual work.
[*][b]Support workflow[/b] - diagnose source archives, verify generated ZIPs, create Nexus-safe report bundles, and export archive structure lists without sharing animation assets.
[/list]

For most OStim Standalone users, use [b]Simple Mode[/b], diagnose the archive, then click [b]Build Recommended Package[/b]. Pandora is the recommended behavior tool for normal OStim Standalone output.

[b]Important: OStim Tools JSON is not a game mod[/b]

OStim Tools / JSON project output is for editing, authoring, review, and manual cleanup. It is not the same as a ready-to-install OStim Standalone ZIP.

To use edited OStim Tools / JSON output in game, import or rebuild it through the normal OStim Standalone package workflow, then run verification and install the generated ZIP.

[b]Behavior generation[/b]

[b]OStim Standalone[/b]

Normal OStim Standalone packages use a pack-specific [b]Pandora-compatible Nemesis/ATT patch[/b]. The generated ZIP includes:

[code]Nemesis_Engine/mod/<UniqueCode>/[/code]
[code]meshes/actors/character/animations/<PackName>/ATT_<UniqueCode>_animlist.txt[/code]

Creature builds additionally include actor-root FNIS lists and matching behavior hooks. Each pack receives a unique code, avoiding shared root AnimData files and cross-pack overwrites. Run Pandora after installing the generated ZIP.

[b]Older Pandora checkbox packages[/b]

Older converter builds could write [i]Pandora_Engine/mod/<PackName>/info.xml[/i] with animationdata/animationsetdata folders. Pandora may display those modules but does not assemble that payload. Reconvert the original archive; current verification deliberately fails that layout.

[b]SexLab / SLAL / P+[/b]

SexLab and P+ exports generate the files needed for SexLab/SLAL workflows, including SLAL JSON/source, renamed stage HKX files, FNIS animation lists, source-provided behavior graph hooks where available, SexLab sound/stage metadata, and P+ registry/SLSB output when selected.

Pandora auto-discovers these SexLab exports from [i]FNIS_<Pack>_List.txt[/i]. They are not expected to appear as selectable Pandora checkboxes. After Pandora finishes, open Engine.log and confirm it contains [i]INFO : FNIS Mod ... : FNIS_<Pack>_List[/i], then register or enable the pack in SexLab Animation Loader in game.

SexLab discovery tags are optional. Enable them if you want [i]AdultAnimationConverter[/i], [i]Converted[/i], and the safe pack name added for easier filtering. Leave them disabled for cleaner source-style tags.

[b]Human-only OStim output and creature packs[/b]

Human-only OStim output is enabled by default for normal OStim Standalone builds. It skips creature and mixed human/creature scenes from mixed SLAL packs and reports how many scenes, roots, HKX files, and behavior events were skipped.

Build Recommended Package uses the value currently shown in the Human-only checkbox. A known-pack recommendation is displayed and logged, but it does not silently change your explicit selection.

Disable Human-only OStim output only if you intentionally want creature scenes and have the required runtime stack. Creature output may require:

[list]
[*]OCreatures or another OStim creature extension.
[*]Creature Framework.
[*]Matching creature assets, such as More Nasty Critters or the source pack's required assets.
[*]Creature-capable Pandora behavior generation.
[/list]

The converter can package creature scenes and actor roots when enabled, and it now writes OCreatures-style OCr<CreatureRoot> menu/index adapter entries for creature-focused OStim output. Reports show whether the OCreatures menu entry was generated, whether retained creature scenes are reachable from that path, which actor-stage mapping was used, and whether FNIS-style creature rows include the expected -Tn flag. The converter does not install the creature runtime stack for you. Creature-only compatibility profiles may recommend creature output instead of human-only output when human-only output would skip every scene.

[b]OStim menu hubs[/b]

When [i]Add OStim menu entry[/i] is enabled, the converter creates a generated OStim menu hub linked from OStim's built-in idle/menu scenes.

[list]
[*]Small packs can link directly from the pack hub.
[*]Large packs are split into generated categories and pages.
[*]Categories include All, Sex, Oral, Vaginal, Anal, Furniture, Creature, Group, and Other where applicable.
[*]Generated scenes can receive return navigation back to the pack menu.
[*]Related scenes can receive Previous/Next navigation when they can be safely grouped.
[*]Verify checks for empty menu hubs, missing destinations, duplicate menu links, and unlinked hub scenes.
[/list]

Furniture-bound scenes may still need to be started from matching furniture. Creature scenes still require a creature-capable OStim setup.

[b]Compatibility notes[/b]

[b]OSex, OSex+, OpenSex, and OSA[/b]

Supported when the archive still includes OSA-style XML scene files and matching HKX animations. Missing speeds, dead scene links, and missing external OSex scene references are repaired or reported where possible.

[b]SexLab and SLAL[/b]

Supported when SLAnims JSON and matching HKX files are present. Large SLAL packs may include furniture, creature, variant, or sparse-tag scenes; the converter reports what was written, skipped, linked, or left out.

[b]FlowerGirls[/b]

Only animation content is converted. Quests, dialogue, spells, scripts, and framework features are not converted. If a FlowerGirls archive only contains .esp, .pex, .psc, or .seq files, install it normally with FlowerGirls instead.

[b]OStim Standalone[/b]

Supported when the archive contains SKSE/Plugins/OStim/scenes JSON plus HKX animations, with or without a top-level Data wrapper. Existing actions and furniture type files are copied/updated where appropriate.

[b]Furniture scenes[/b]

Furniture scenes are counted separately in reports. Built-in furniture scenes should be started from matching furniture in OStim. Spawned-prop or custom object scenes are kept selectable unless they safely map to a real OStim furniture type.

[b]Do not reuse old converted ZIPs[/b]

If a pack failed with an older converter version, reconvert the original source archive with the latest version. Do not keep testing an old generated ZIP.

Also remove or disable older converted versions of the same pack before testing a new one. Old converted outputs or old Pandora/Nemesis generated output can cause duplicate entries or idle actors even when the new ZIP is clean.

[b]Troubleshooting[/b]

[b]The bottom of the app is cut off[/b]

Use the latest version. The main window is scrollable/resizable so lower controls remain reachable on smaller screens or high-DPI Windows scaling.

[b]Windows Defender says the app is a virus[/b]

Use the current folder-style release ZIP instead of an older single-file EXE. Extract the whole Adult Animation Converter folder and run the EXE from inside that folder. Do not copy the EXE away from its [i]_internal[/i] folder. Current builds use a fresh pinned environment, disable UPX, embed version metadata, reject unrelated runtime packages, and include BUILD_PROVENANCE.txt.

The download includes README_SECURITY.md and SHA256SUMS.txt. Compare the published SHA256 hash with your downloaded file. [i]Windows protected your PC[/i] is a SmartScreen reputation warning, not a named Defender Antivirus detection. If Defender gives a named detection, do not disable protection or add a broad exclusion. Keep the file quarantined, record the exact detection name and hash, and submit an incorrectly detected clean release here:

[url]https://www.microsoft.com/en-us/wdsi/filesubmission[/url]

[b]Nemesis shows a converted-pack checkbox with (null)[/b]

Do not tick it. Reconvert the original archive with the latest converter. Current OStim Standalone output uses Pandora-compatible Nemesis/ATT registration and does not require that checkbox.

[b]Nemesis reports ERROR(2006) with File: animationdata[/b]

Remove the older converted ZIP from your mod manager, rebuild the original archive with this version or newer, install the fresh ZIP, and rerun the behavior tool recommended by the report. Older builds wrote Pandora-style metadata under Nemesis_Engine, which Nemesis can mistake for a missing behavior XML patch.

[b]Pandora shows duplicate entries[/b]

First verify the generated ZIP. If Verify passes and reports no duplicate behavior registrations, remove older converted versions of the same pack, remove old Pandora generated output if applicable, install the fresh generated ZIP, rerun Pandora, and enable/deploy only the newest Pandora output.

If Verify reports duplicate or conflicting registrations, do not install the ZIP. Attach the human-readable report when posting a bug.

[b]Pandora shows the converted pack but actors stay idle[/b]

Reconvert the original archive with the latest converter, install the new [i]_OStimSA.zip[/i], rerun Pandora, and make sure Pandora's generated output mod is enabled/deployed in your mod manager.

Visibility in Pandora does not always mean the motion events from an old converted ZIP were registered.

Import Pandora's Engine.log after the run. Version 5.7 and newer recognize Pandora 4.4 OutputAnimData/OutputAnimSetData merge messages and check for generated behavior files beside that log. A saved output-path warning is applied only when those settings match the imported log folder.

[b]The converted OStim menu appears but is empty[/b]

Open the report and check the menu hub / category visibility section. If valid scenes were written but not linked, attach the report bundle. If Human-only OStim output skipped all creature scenes, the report will say that no human scenes were retained.

[b]Creature pack does not appear in the OCreatures creature menu[/b]

Open the report and check the OCreatures Output and OCreatures Menu Integration sections. Creature-focused OStim output should say that the OCreatures menu entry was generated and that retained creature scenes are reachable from the OCreatures menu path. If those pass, check runtime setup next: OCreatures or another OStim creature extension, Creature Framework, matching creature assets, installed converted ZIP, and enabled/deployed Pandora output.

[b]Converted scenes do not appear in game[/b]

[list]
[*]Make sure you installed the generated ZIP, not the original source archive.
[*]Run the behavior tool recommended by the report.
[*]Make sure the generated behavior output is enabled/deployed.
[*]For OStim output, check OStim's scene UI and the generated menu hub.
[*]For SexLab output, register or enable the pack in SexLab Animation Loader.
[*]For human-only OStim output, read the skipped creature counts in the report.
[*]For included creature scenes, confirm the correct creature runtime, assets, and behavior generation are installed.
[/list]
